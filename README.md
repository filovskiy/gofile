# gofile

Анонимная передача файлов между пользователями по **hex-id**.
Весь сайт — одна статическая страница на GitHub Pages, хранилище — сам репозиторий через GitHub Contents API. Без серверов, аккаунтов, куков и аналитики.

**Сайт:** https://filovskiy.github.io/gofile/

## Как это работает

1. Отправитель выбирает файл. Браузер генерирует случайный **hex-id** (32 символа).
2. Из hex-id выводится ключ AES-256-GCM (PBKDF2, 150 000 итераций) — файл **шифруется до отправки**. Имя файла внутри хранилища — HMAC от ключа, поэтому по списку файлов в публичном репозитории нельзя восстановить ни один id.
3. Шифртекст загружается в `files/YYYY-MM-DD/<hmac>.bin` через GitHub Contents API.
4. Получатель вводит hex-id (или открывает ссылку `…#id=…`). Его браузер сам выводит ключ из id, вычисляет путь к блобу, скачивает и расшифровывает. **Для скачивания ничего не нужно — ни токенов, ни аккаунтов.**

Формат hex-id: `6 hex` (день загрузки, для срока жизни) + `26 hex` случайных (104 бита энтропии).

## Токен (обязательный шаг для загрузок)

У GitHub нет анонимного API записи, поэтому загрузки идут через fine-grained PAT, вписанный в `config.js` (скачивание работает всегда без токена).

1. GitHub → **Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**.
2. **Repository access:** Only select repositories → `gofile`.
3. **Permissions → Repository permissions → Contents: Read and write** (больше ничего не давать).
4. Скопируйте токен и вставьте в `config.js` в поле `token`, закоммитьте в `main` — сайт передеплоится автоматически.

Кто угодно может вытащить токен из публичного репозитория, поэтому он должен давать доступ **только к этому репозиторию и только к Contents**: худшее, что сможет сделать злоумышленник — заполнять `files/` мусором или удалять чужие шифртексты (это чинится `purge`-workflow'ом и не раскрывает расшифрованные данные).

Альтернатива: не вписывать токен в конфиг, а вставить его в поле на сайте — тогда он сохранится в localStorage только вашего браузера.

## Лимиты и обслуживание

| Параметр | Значение | Где менять |
|---|---|---|
| Макс. размер файла | 40 МБ (лимит Contents API) | `config.js → maxBytes` |
| Срок хранения | 7 дней | `config.js → ttlDays` + `purge.yml` (`7 days ago`) |
| Загрузки | ~5000/час на токен (общий для всех) | — |
| Скачивания | без ограничений (CDN) | — |

Workflows:
- **deploy** — публикует сайт на Pages при изменении `index.html/app.js/styles.css/config.js`;
- **purge** — ежедневно удаляет директории `files/…` старше 7 дней (UTC);
- **gc** — еженедельно сжимает историю в один коммит, чтобы репозиторий не пух от коммитов загрузок.

## Приватность

- Нет аккаунтов, регистрации, куков, внешних шрифтов/CDN/аналитики — страница не делает ни одного запроса кроме `api.github.com` и `raw.githubusercontent.com` (см. CSP в `index.html`).
- Исходное имя и содержимое файла покидают браузер только в виде шифртекста; ключ = сам hex-id, на сервер не отправляется.
- Что неизбежно видит GitHub: IP-адреса, время коммита, размер шифртекста. Метаданные старых загрузок стираются `gc`-workflow'ом.
- После удаления файла CDN `raw.githubusercontent.com` может отдавать его ещё несколько минут из кэша.
